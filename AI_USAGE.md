# AI Usage

## Status

**AI-assisted functionality: none.**

OnTrack Project Intelligence currently does not use artificial intelligence, machine learning, generative AI, an AI API, or an LLM.

## Assessment Mechanism

Project health is determined by explicit, deterministic rule-based logic implemented in the backend intelligence module.

Examples include:

- deadline comparisons
- elapsed project duration versus reported progress
- update freshness thresholds
- progress percentage thresholds
- keyword matching on recent updates
- incident severity and count
- uptime, response time, and error-rate thresholds
- deployment failure rates
- evidence completeness and update count

## AI/LLM APIs

The application does not call:

- OpenAI
- Azure OpenAI
- Gemini
- Claude
- Hugging Face
- any vector database
- any text-embedding service
- any hosted or local generative model

## How Findings Are Produced

Findings are generated by `ScheduleHealthCalculator`, `ProgressHealthCalculator`, `OperationalHealthCalculator`, and `EvidenceHealthCalculator`.

The process is explainable:

1. Read project master and evidence from PostgreSQL.
2. Compare source values with implemented thresholds.
3. Generate a finding with category, severity, confidence, reasoning, impact, and recommended action.
4. Sort and prioritize findings.
5. Create automated follow-ups for `CRITICAL` and `HIGH` findings.

No probabilistic classification or generative text is used.

## Existing AI-Related Fields

Terminology such as "confidence" in this application means the system's certainty based on the availability and freshness of evidence. It is not a model-generated probability or a machine-learning confidence score.

Likewise, generated finding descriptions and follow-up text are composed from explicit rule templates and source values, not by an AI model.

## Explainability

Each persisted finding is intended to include:

- The rule category
- A human-readable title and description
- A severity
- A confidence level
- Reasoning
- Impact
- Recommended action
- Evidence references where available

## Potential Future AI Usage

AI or an LLM could be considered later for optional capabilities such as:

- summarizing long status updates
- clustering recurring project issues
- drafting executive summaries
- extracting structured evidence from documents
- proposing follow-up wording

Before implementation, such features would require:

- explicit product approval
- human review
- data privacy and security controls
- prompt and model version tracking
- deterministic fallback behavior
- clear indication of whether text is AI-generated
- testing for hallucination and inaccurate source attribution

At present, no such features are enabled.
